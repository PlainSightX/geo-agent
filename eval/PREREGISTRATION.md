# 评测预注册

本文件与 `questions.json`、`gold.json` 在任何模型调用之前提交到 git；以提交时间为准。
之后对题目、金标、判分规则的任何改动都必须在报告中逐条披露，并说明对结论的影响。

## 研究问题

在同一模型（`deepseek-chat`）、同一份 schema 文本、同一组问题下，
“类型化 GIS 工具 + 确定性校验 + 有限修复”的 Agent，是否比“一次性 text-to-SQL”更准确、更少单位/CRS 错误，代价是多少调用与费用。

## 数据

南京市 OSM 快照（Geofabrik `jiangsu-261017.osm.pbf`，sha256 见 `data/SOURCE.json`），
按南京市行政边界裁剪后的 7 张表。金标结果依赖该快照，换快照必须重新冻结。

## 题目

- 测试集 `questions.json`：61 题，7 个层级。attribute 8、distance 9、nearest 8、district 10、multistep 9、crs_unit 8、unanswerable 9。
- 开发集 `dev_questions.json`：10 题，问题与测试集不同，只用于调试 Agent 与提示词。
- 测试集只完整运行一次（每个臂一次，temperature=0）。若因基础设施故障（网络、API 5xx）中断，只重跑失败的题，并在报告中注明。
- 金标 SQL 由作者手写；每题冻结执行结果与 sha256。
- 冻结前做边界裕度检查：半径/阈值题中所有候选对象的值与阈值相差 ≥ 0.5%；top-k 题第 k 与 k+1 名相差 ≥ 0.5%。
  检查失败的题改了半径或 k（B08 1 km→1.2 km、C08 3→2、E03 500 m→400 m、E09 改问酒店），都发生在冻结前，原因记录在 git 历史里。

## 两个评测臂

| | (a) 单次 text-to-SQL 基线 | (b) Agent |
|---|---|---|
| 模型 | deepseek-chat, temperature 0 | 同左 |
| 上下文 | schema 文本 + 规则说明 | 同一份 schema 文本 + 工具说明 |
| 输出 | 一次调用，JSON：`{"sql": ...}` 或 `{"refuse": true, "reason": ...}` | LangGraph 循环：工具调用 → 校验 → 最多 3 次修复 → `final_answer` |
| 工具 | 无 | 自省（find_entity、distinct_values）、run_sql（守卫）、类型化 GIS 工具 |
| 上限 | 1 次调用 | 最多 8 次模型调用 |

两臂的 SQL 都经过同一个守卫（只读白名单）并在同一只读角色下执行。

## 判分（全部确定性，不用 LLM 打分）

- **主要指标：总体正确率（61 题）**。可回答题：最终结果集与金标匹配；不可回答题：系统明确拒答。
- 结果集匹配规则见 `src/geo_agent/matcher.py`：预测可多出列；金标列需单射映射到预测列；行按多重集合比较（D06 要求顺序）；数值相对误差 ≤ 0.5%。
- Agent 的“最终结果”是 `final_answer.result_ref` 指向的那次工具结果；基线的最终结果是其 SQL 的执行结果。
- 可回答题被拒答记为错误；不可回答题给出任何数值/结果记为错误。
- 次要指标：
  - 可回答题执行准确率（52 题）、拒答正确率（9 题）；
  - 有效 SQL 率：模型生成的每条原始 SQL 中，通过守卫且执行成功的比例；
  - 单位/CRS 错误率：在金标 SQL 含 ST_Distance / ST_DWithin / ST_Area / ST_Length 的题上（由脚本自动识别），最终 SQL 被静态检查判为“在 EPSG:4326 几何上直接做米制计算”，或最终数值与金标相差 10 的整数次幂（±2%）的比例；
  - 每题模型调用次数、输入/输出 token、费用（$0.30 / $1.20 每百万 token 估算）、端到端延迟。
- 统计：比例给 Wilson 95% 区间；两臂配对比较用精确 McNemar 检验（双侧二项）。

## 预算

API 总花费上限 4 美元（含开发集调试）。每次调用写入 `eval/runs/ledger.jsonl`，累计超过 3.6 美元时脚本拒绝继续调用。

## 已知局限（预先声明）

- 金标代表一种合理口径（如“区内”= ST_Within 点在面内、道路长度按区界裁剪），其他口径的合理答案会被判错；失败案例逐题列出，供读者判断。
- 61 题的样本量只够检测较大差异；区间宽度在报告中给出。
- OSM 数据不完整（如很多酒店无名称），结论只针对该数据快照，不代表真实世界的设施数量。
