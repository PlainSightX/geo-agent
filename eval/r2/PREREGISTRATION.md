第一轮发现：在带详细中文注释的 schema 和偏简单的题上，Agent 与单次 text-to-SQL 没有可分辨差异（57/61 vs 56/61，p=1.0）。

## 路网口径（金标与工具共用）

- 步速 4.8 km/h = 80 m/min；“N 分钟步行”= 80·N 米**网络距离**。
- 吸附：要素代表点（点即自身；面取 `ST_PointOnSurface`；同名多要素取 id 最小者）→ 最大连通分量中 KNN 最近顶点；吸附段不计入距离。
- 最短路：`pgr_dijkstra` 无向，边权 = 边长（米）。
- 可达设施：设施吸附顶点的网络距离 ≤ 阈值。
- 等时圈面积：两端点都可达的边，在 EPSG:32650 上 2 m 简化、50 m 缓冲（quad_segs=2）后求并，geography 面积。
- 学段识别：OSM 只有 amenity=school，不区分学段；本项目“中学/初中”= `subtype='school' AND name LIKE '%中学%'`，
  “小学”= `name LIKE '%小学%'`。这是一个**明确的口径选择**，名称不含“中学”的初中会被漏掉（README 局限中说明）。

## 题目（72 题，6 层）

| 层 | 题数 | 考察 |
|---|---|---|

| join 多表/消歧/别名 | 12 | alt_name/old_name 别名、同名多校区、点在面内的区归属、跨表最近邻 |
| crs 投影与度量 | 10 | 公顷/平方米/公里换算、周长、Web 墨卡托放大倍数、按区界裁剪长度 |

| compliance 标准合规 | 12 | 检索条文得到服务半径 → 路网可达判定；6 题“符合”、6 题“不符合” |

题目写作规则（防止偏向任一臂）：题面用自然中文，**不提示**表名、列名、标签键或函数名；路网题写明步速与“沿步行路网”，
等时圈题写明 50 m 缓冲口径——这些是口径而非解法，两臂看到同样的题面。合规题不在题面给出服务半径数值，需要从条文得到。

冻结前的自动检查（`freeze_gold.py`）：结果非空、无截断、计数非 0；直线阈值题所有候选与阈值相差 ≥ 0.5%；
路网阈值题（含合规题）所有候选设施的网络距离与阈值相差 ≥ 1%；top-k 题第 k/k+1 名相差 ≥ 0.5%。
冻结前的检查改动了 5 道题（记录在 git 历史中）：J05 半径 100→120 m（有站点在 100.08 m）；
D12/D13/D16 原始选点结果为 0，换成非零的起点或半径；J08 原题会把品牌标签为麦当劳的“自助点餐机”算作麦当劳，改为限定快餐店并只比较距离。

## 两个评测臂（同一模型 `deepseek-chat`，temperature 0）

| | (a) 单次 text-to-SQL | (b) Agent |
|---|---|---|
| schema | 精简 schema（`r2_schema.describe_lean_schema`）+ 同一份函数说明 `FUNCTION_NOTES` | 同左 |
| 规则 | 同一份 `R2_COMMON_RULES`（坐标系、步速、合规口径、拒答规则、合规题的输出列约定） | 同左 |
| 条文 | 可在 SQL 中查询 `standard_clauses`（按 facility/title 过滤；SQL 中无法计算向量） | 额外有 `retrieve_standard(query)`：本地 bge-small-zh 向量检索 top-k 条文 |
| 工具 | 无，一次调用、一条 SQL | 第一轮全部工具 + `walk_route`、`isochrone`、`reachable`、`retrieve_standard`、`run_sql`（含 pgRouting） |
| 修复 | 无 | 校验器（守卫/执行错误/单位/空结果/截断/合规答案缺条文或阈值不一致）+ ≤3 次修复，≤10 次模型调用 |

可选的消融臂 (c)：Agent 去掉 `walk_route/isochrone/reachable/retrieve_standard` 四个工具（仍可写 pgRouting SQL），其余同 (b)。

每臂完整运行 3 次（`r2run1..3`）。主分析用 run1；同时报告 3 次的均值与逐次结果。
基础设施故障（网络、5xx）导致的中断只补跑失败题并标注；不因结果不理想重跑。

## 判分规则（确定性，不用 LLM 打分）

- 结果集比对沿用第一轮 `matcher.py`：预测可多出列；金标列单射映射到预测列；行按多重集合比较（`order_matters` 题按顺序）；
  数值相对误差 ≤ 0.5%。
- 实现：`src/geo_agent/matcher_r2.py`（与本文件同一提交冻结）。最短路题金标只保留题面问到的量（米或分钟），不要求多答。
- **路网层**（route 层全部 16 题；距离、分钟、面积）数值相对误差放宽为 ≤ 2%（该层计数都 < 30，2% 对整数计数等同精确）：同一口径下不同的合理写法
  （例如吸附到“最近顶点”还是“最近边上的投影点”）会带来几十米差异，2% 足以区分写错与写法差异，
  但会接受“吸附段计入/不计入”这类小差别。计数与名称列表仍要求精确。
- **合规题**：预测结果必须含一个布尔列（或可解释为布尔的 0/1、'是'/'否'、'符合'/'不符合'）与金标 `compliant` 一致，
  **且**结果中某列的值等于金标条文 id（`clause_id`，字符串精确匹配）。只给结论不给条文、或条文 id 错误，判错。
  `radius_m` 列不要求（若提供，必须等于条文中的数值，否则判错——这是“条文数字被程序约束”的检查）。
- 不可回答题：系统明确拒答为对；给出任何结果为错。可回答题被拒答为错。
- 次要指标：按层正确率；有效 SQL 率；单位错误（沿用第一轮静态检查 + 数量级检查）；调用次数、token、费用（$0.30/$1.20 每百万 token 估算）、延迟；
  失败类型（解析失败、执行错误、超时、拒答、结果不符）。
- 统计：Wilson 95% 区间（run1 与 3 次合并两种）；run1 配对精确 McNemar（a vs b，以及 b vs c 若运行）；3 次之间的题级一致率。

## 预算

用户确认 API 费用不是约束；仍按 `deepseek-chat` 单一模型运行，每次调用写入同一份台账 `eval/runs/ledger.jsonl`。
第二轮把台账停止线提高到 $20（`GEO_AGENT_BUDGET_STOP_USD`），预计实际 < $3。

## 已知局限（预先声明）

- 题目与金标仍由作者一人编写，代表一种口径；尤其“中学”按名称识别、小区按 OSM landuse=residential 面、设施按 OSM 标签。
- “合规”只是按标准推荐服务半径（“不宜大于”，非强制性条文）做的空间核查，不等同规划审批意义上的合规结论。
- 步行路网来自 OSM，人行道、过街设施和小区内部道路缺失较多；部分小区代表点到路网的吸附距离超过 100 m。
- 72 题仍是小样本，单臂区间宽约 ±10 个百分点。
